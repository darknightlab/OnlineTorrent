# 单集页推荐规则（默认值的设计与场景）

单集页按「推荐规则」给每个文件打分，排序后自动播放第一个（`web/src/lib/rank.ts`；规则存于设置 `rank.rules`，后台「推荐规则」页编辑，`internal/rank` 校验）。本文记录默认值的依据（第二版 e23a33a、第三版 708decc、第四版 tanh、第五版为店主指定的当前默认值）。场景同时是测试：`web/src/lib/rank.scenarios.test.ts`（下表由测试数据生成）。

## 问题（第一版默认值）
第一版「服务器已缓存 +30、每个 WebRTC 做种者 +5（上限 30）」使可用性压倒一切：某个资源一旦被服务器缓存，之后出现更好的版本（有中文字幕的字幕组、更小的 HEVC、做种更多）也不会换；文件大小除超限外不影响排序。按下表场景，第一版只选中 24/39 个首选（另有 8 个可接受），7 个选错（01 03 08 10 24 30 36：生肉 / 繁体因为已缓存压过简体）。

## 判断原则（人工）
按优先级：
1. **现在对这个用户能播**：游客（无做种 / WebSeed 权限）只能从 WebRTC 节点拿数据（本站 qB 做种时也是一个 WebRTC 节点）；会员还能让服务器从 BT 下载。确定放不了的排后；从未统计的不算放不了。策略不允许的（第四版起）后端直接不返回。
2. **中文字幕**：简体 > 繁体 > 日文 > 无（生肉、英文字幕）。「简繁」「简日」等同简体。
3. **清晰度**：4K > 1080p > 720p > 更低；大文件由大小扣分平衡（第四版起 4K 优先，只要不太大）。
4. **文件小 / HEVC**：P2P 与服务器流量都更省。
5. **可用性余量**：做种人数，只在以上都差不多时起作用。
同分时较新的在前（修正版通常更新）。

## 默认规则（第五版，店主指定）
第四版去掉「服务器已缓存 +2」：用户不应知道本站服务器缓存了什么（`server_complete` 已从所有面向用户的接口移除，见 api.md「做种统计」）。本站 qB 做种时经 wss tracker 计入 WebRTC 做种人数，所以不需要单独加分。

| 项 | 值 | 说明 |
|---|---|---|
| WebRTC 做种 | 20 × tanh(n / 20) | 1 人 +1、5 人 +4.9、20 人 +15.2，趋近 +20；对所有用户 |
| BT 做种（仅有做种权限的用户） | 10 × tanh(n / 20) | 3 人 +1.5、23 人 +8.2，趋近 +10 |
| 无人做种 | −100 | 游客类（无做种 / WebSeed 权限）：WebRTC 0；有做种或 WebSeed 权限：BT 0 且 WebRTC 0。未统计（或该类 tracker 无响应）不扣 |
| 简体 / 繁体 / 日文（分组「字幕」） | +25 / +20 / +10 | 同第四版 |
| 4K 及以上 / 1080p / 720p（分组「分辨率」） | +30 / +20 / +10 | 更低 0 |
| HEVC | +2 | |
| 文件大小 | ≤ 200 MB 0；1000 MB −16；之后继续（2 GB ≈ −37） | |

- −100 仍是决定性的：最大加分 25 + 30 + 20 + 10 + 2 = 87。
- 旧规则里的 `server_complete` 读入时忽略；库中等于任一旧版默认值（含第四版）的规则启动时替换为第五版。

### 第五版的场景变化
场景输入去掉「服务器已缓存」：原来标为已缓存的候选改为至少 1 个 WebRTC 做种（本站 qB 经 wss tracker 计入），其余不变。两个场景的首选随之改变（都是原来的「可接受」项）：
| 场景 | 原期望 → 新期望 | 原因 |
|---|---|---|
| 24 游客：繁体（原已缓存，RTC 3）vs 简体（RTC 1） | 繁体 → 简体 | 少了 +2，简体以 1 分领先，回到「差不多时选简体」 |
| 40 真实：学生会也有洞！03（会员） | 简繁 TV 版 → 喵萌简体 | 少了 +2，更小的喵萌简体（BT 226）略领先 |

- 「超过自动选种大小上限 −10」已删除（旧规则里的 `oversize` 字段读入时忽略）。
- 当前用户无权播放（内容策略）的种子**后端根本不返回**（单集、条目种子列表、搜索、选集资源数、`/meta/v1` 单集文件），评分里不再有「不可播放排最后」。管理员看到全部（含被屏蔽的，自动播放会跳过非 allow 的）；直接打开（play）仍按策略拒绝。
- −100 仍是决定性的：最大加分 = 25 + 30 + 2 + 20 + 10 + 2 = 89。
- 新增的规则写法（后台可改）：做种曲线 `tanh`（系数 × tanh(人数 / 尺度)，`wt_scale` / `bt_scale`；`log` / `linear` 保留）；文件大小为两点直线 `{from_mb, from_score, to_mb, to_score, extend}`，`extend` = 终点后继续延伸。旧写法 `{max, full_below_mb, zero_above_mb}` 读作 (full_below_mb, max) → (zero_above_mb, 0)。

### 第四版的场景变化
- 现有 39 个场景（删去 2 个后）的首选**都没有变**，无需改期望。
- 删去 23、35：「策略不允许」的资源不再到达前端评分。
- 新增 42–45：日文字幕胜过生肉；4K HEVC 900 MB 胜过 1080p AVC 600 MB（只大 300 MB，1080p 也可接受）；游客 20 个 WebRTC 节点的繁体胜过 1 个节点的简体（简体也可接受）；标题里的「日常」「日本」不算日文字幕。

## 升级
默认规则在首次启动时写入设置表，因此已部署的库里存的是旧版默认值。启动时若库里的 `rank.rules` 与某个旧版默认值（第一版 7d2effb、第二版 e23a33a、第三版 708decc、第四版 tanh；JSON 相等）完全相同，即替换为当前默认值；管理员改过的规则保持不变（`rank.IsLegacyDefault`，`store.seedSettings`）。
